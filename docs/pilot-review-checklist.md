# مراجعة تجربة الأساسيات وSOC

## التجربة الذاتية أولاً

افتح [صفحة تجربة التعلّم](https://academy.biuret.dev/pilot.html) بحسابك، واتبع الخطوات الثماني. كل رابط يفتح تبويباً آخر لتحتفظ بنموذج الملاحظات. جرّب أولاً دون مساعدة. سجّل ما توقعته وما حدث وموضع المشكلة. اختيار «أنجزتها دون مساعدة» هو ملاحظة استخدام ذاتية، وليس نتيجة امتحان.

ابدأ بالأساسيات. يمكن تسجيل SOC كـ«المحتوى مقفل لحسابي» إذا لم تُستوفَ شروط الوصول. تجربة حساب الإدارة تفحص العرض والأدوات، لكنها لا تثبت صحة ترتيب فتح المحتوى لحساب متعلم جديد. لا نرفع صلاحيات حساب متعلم لغرض الاختبار.

الملاحظات محفوظة لحسابك في المتصفح نفسه. نزّل `biuret-learning-trial.json` وأرفقه في المحادثة عند الانتهاء. راجع النص الحر قبل المشاركة. لا يتضمن التقرير تلقائياً الاسم أو البريد أو معرف الحساب. لا يُرسل التقرير إلى خادم، ولا يتطلب تجربة دفع أو بدء امتحان.

## تحويل الملاحظات إلى إصلاحات

أنشئ لكل مشكلة سطراً في `pilot-issues.csv`، مع خطوات إعادة الإنتاج، واللغة، والنتيجة المتوقعة والفعلية، ومعيار قبول قابل للفحص. العائق الذي يمنع درساً متاحاً أو يفقد إجابة له الأولوية؛ القفل المتوقع يوثق كملاحظة وليس عيباً تلقائياً.

| الأولوية | المعنى | مثال لمعيار القبول |
| --- | --- | --- |
| P0 | كشف إجابات خاصة أو تجاوز الوصول أو منح إنجاز خاطئ | رفض الطلب من الخادم وعدم ظهور محتوى مقفل |
| P1 | يمنع مهمة أساسية أو يفقد عمل المتعلم | يستطيع المتعلم استعادة الإجابة بعد التحديث |
| P2 | يسبب ارتباكاً أو خطوة غير ضرورية | يستطيع تحديد الزر التالي ومتطلباته دون مساعدة |
| P3 | تحسين مظهر أو صياغة مع بقاء المهمة واضحة | النص والاتجاه والمسافات مقروءة في اللغتين |

الحالات: `new → reproduced → fixing → retest → closed`. سجّل دليلاً لإعادة الاختبار قبل الإغلاق. لا تدرج أسراراً أو هوية المتعلم في السجل العام. لا توجد نتائج تجربة بشرية مسجلة حتى الآن.

## مراجعة مختص لاحقاً — لا تُعد التجربة الذاتية بديلاً عنها

هذه قائمة للمراجع المستقل. لا تتضمن مفاتيح الإجابة الخاصة ولا تمنح وصولاً تلقائياً لها.

| وحدة | ما يراجعه المختص | تمرين أو دليل مطلوب |
| --- | --- | --- |
| URL | المضيف الفعلي، حدود TLS، userinfo والتحويلات | يفسر المتعلم وجهة رابط وحقيقة لم يتم إثباتها |
| الهوية | المصادقة والتفويض وإبطال الجلسة وأقل صلاحية | اختبار مسموح وآخر مرفوض، والتحقق من الإبطال |
| الأدلة | UTC، حفظ الأصل، التجزئة وحدود الاستنتاج | سجل تعامل مع الأدلة، وتفسير فجوة جمع السجلات |
| SOC والشبكات | جلسة وهوية وجهاز مقابل عنوان NAT مشترك | حالة مرتبطة وحالة تشابه غير مرتبطة |
| SOC والتشفير | ما تثبته الحماية وما لا تثبته | فصل تشفير النقل عن اعتماد السلوك |
| SOC والاستجابة | فرضيات بديلة واحتواء متناسب وتحقق | تقرير قصير: دليل، مجهول، إجراء، تحقق |
| جودة الكشف | فصل الحالات المحسومة عن غير المحسومة والتغطية | حساب بمقام مبرر؛ بيان متى لا يمكن حساب الاستدعاء |
| امتحان المسار | كل مهارة مقيمة لها تعليم مطلوب وتطبيق | خريطة السؤال إلى هدف مطلوب، دون تسريب السؤال |

لكل وحدة يضع المراجع: `needs correction / needs teaching / ready for pilot` مع السبب والمرجع. يفحص أيضاً وضوح العربية والإنجليزية وتكافؤ الصعوبة، وعدم كشف الإجابة بطول الخيار أو تكرار صياغة المثال. لا نستخدم «معتمد من مختص» حتى تتم هذه المراجعة فعلياً.

القرار التالي بعد تقريرك: إصلاح العوائق، إعادة التجربة، ثم مراجعة مختص وتجربة مبتدئين مستقلين قبل فتح الشراء. لا تُحوّل نتيجة مكتب التحليل المحلية أو استمارة الملاحظات إلى دليل شهادة.
